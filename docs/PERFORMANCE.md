# Local performance baseline — 2026-09-16

The reproducible raw record is `benchmarks/initial.json`. Run it again locally:

```sh
python3 dev.py bench --sizes 500 1000 2000 --samples 11
```

The benchmark uses the same `compile()` pipeline as the CLI. Each timed sample
includes parsing, structural inference, refinement checking, bytecode emission,
structural bytecode validation, type rendering, and destruction of compiler state.
It excludes C++ compiler construction, process startup, source generation, file
I/O, artifact encoding, and execution of the generated bytecode. There is no
resident source cache in this revision. Small equivalent workloads are run against
independent expected integer results before timing; large benchmark programs are
not claimed to have been executed through unrestricted recursion.

These are measurements on a shared Linux x86_64 execution host, GCC 14.2.0 Release,
not guaranteed latency targets. Raw samples, compiler flags/version, source and
binary SHA-256 identities, CPU/platform details, and deterministic work counters
are retained. Inputs and binary hashes are checked before/after measurement.

| Size | Wrapper chain | Wide record/projections | Polymorphic uses | Refinement calls |
| ---: | ---: | ---: | ---: | ---: |
| 500 | 4.440 ms | 3.141 ms | 9.240 ms | 2.086 ms |
| 1000 | 8.109 ms | 7.345 ms | 14.950 ms | 4.358 ms |
| 2000 | 17.125 ms | 17.536 ms | 40.259 ms | 9.032 ms |

The row-projection experiment replaced repeated whole-record inference traversals
with known-field lookup and skipped instantiation walks for monomorphic schemes.
The current wide-record workload uses 32 type nodes and zero instantiation visits
at each measured size. Projection-step counts equal the number of projections.
That is a bounded-work observation, not a proof of global linear complexity:
lookup, evidence maps, rendering, and other traversals still have costs.

Earlier exploratory wall times are not published as a controlled speedup claim.
The fully fingerprinted record here is the baseline for future paired experiments.
The driver enforces work-growth checks for these workloads and recomputes medians
from the raw observations; wall-clock thresholds are not hard-coded for arbitrary
machines. Broader workload diversity, cold-start latency, memory growth, resident
edits, production runtime performance, and statistically matched comparisons are
open gates in `PRODUCTION_READINESS.md`.

Building this initial header-heavy C++ compiler itself is considerably more
expensive than checking a TT program. A foreground clean build exceeded one local
tool invocation's execution timeout and was resumed; it was not a compiler/test
failure. Do not confuse that development-build time with the timings above.
