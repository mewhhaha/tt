# Status delta — 2026-09-17 — Wasm live heap lifetime

Current main remains a research prototype and keeps the same Node.js compiler / WebAssembly-only target boundary. Commit `582989f17816cab6b7bb4afea7fd4ea02d98cf4b` hardens host result decoding around the per-`main` bump-allocation lifetime without adding imports, a JavaScript evaluator, a custom bytecode target, native output, or a public Wasm export.

New artifacts publish the final successful bump cursor in private reserved memory word 12. The word is cleared before each invocation and written only after the source entry returns. The host decoder now separates static `[16, heap_start)` from current dynamic `[heap_start, live_heap_end)` storage, rejecting object spans across that boundary and pointers into grown-but-unallocated page capacity. A failed invocation advertises no live heap. Older ABI-2 artifacts leave the watermark zero and retain the previous page-bounds compatibility path.

`execute(...).metrics.heap_bytes` now reports the dynamic bump bytes allocated by the successful invocation. It is not peak memory or retained-live-object size.

Local evidence in this iteration used Node 22.16.0 on Linux. The changed production-file baselines were reconstructed byte-for-byte from live main before modification. Targeted exact-current-backend tests were 22/22, including existing ABI-integrity, source-location/provenance and Wasm runtime cases plus four new lifetime regressions. The recovered full Wasm handoff with the same change passed `npm test` at 104/104 and `npm run verify`, including four examples, README, standalone Wasm, 500/1,000/2,000 compiler work gates and the 1,000-element map/fold engine-stage check. Explicit compiler and runtime benchmark commands also passed. No CI result was used.

The exact current backend artifact delta was +21 bytes for `return 1;` and +20 bytes for representative arithmetic, array and map programs, with no public-export or Wasm-function-count change. Timing samples are observations only; no speed claim is made.

Production-readiness gates remain open. This does not add GC, reclamation, persistent host objects, host-callable returned closures, hostile-module isolation, variants/recursion, modules, nominal declaration evidence, effects/staging or the ECS vertical slice. Next allocator work should audit nested/aggregate liveness and define the ownership/host-lifetime boundary rather than treating the private watermark as memory management.
